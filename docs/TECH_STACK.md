# 프로젝트 기술 스택 및 구현 지침

## 1. 크로스 플랫폼 개발 환경

### 기술 스택
- **Framework:** Flutter
- **Language:** Dart
- **SDK Version Management:** FVM

### 구현 지침
- Android와 iOS를 하나의 Flutter 코드베이스로 개발한다.
- 화면(UI), 비즈니스 로직, 데이터 처리 계층을 분리한다.
- 공통 UI 컴포넌트를 재사용한다.
- 카메라, 갤러리, 로컬 저장소는 호환되는 Flutter 패키지를 활용한다.
- FVM으로 Flutter SDK 버전을 고정하고 관리한다.
- 새로운 패키지를 추가하기 전에 기존 의존성과의 호환성을 확인한다.

## 2. 데이터 저장 및 기기 간 동기화

### 기술 스택
- **Backend:** Firebase
- **Database:** Cloud Firestore
- **Authentication:** Firebase Authentication
- **Access Control:** Firebase Security Rules
- **Local Storage:** Flutter 호환 로컬 데이터베이스 또는 저장소 패키지

### 구현 지침
- 분석 이력은 로컬 저장소에 저장하고 조회, 수정, 삭제할 수 있도록 구현한다.
- 앱을 재실행해도 기존 분석 이력이 유지되도록 한다.
- Firebase는 기기 간 분석 이력 동기화를 위한 선택적 기능으로 구현한다.
- Firestore 사용 시 사용자별 데이터 구조를 설계하고 보안 규칙을 설정한다.
- 실시간 동기화가 필요한 데이터에는 Firestore 리스너를 활용한다.
- 네트워크 연결이 없어도 로컬 분석 이력을 확인하고 관리할 수 있도록 한다.
- Firebase와 로컬 저장소의 데이터 처리 계층을 분리하여 핵심 기능이 Firebase에 의존하지 않도록 한다.

## 3. 이미지 분류

### 기술 스택
- **AI Runtime:** Google AI Edge LiteRT
- **Classification Model:** MobileNetV3
- **Execution Environment:** On-device Inference

### 구현 지침
- MobileNetV3 모델을 LiteRT 호환 형식으로 준비하고 Flutter 앱에 연동한다.
- 이미지 분류는 서버 호출 없이 모바일 기기에서 실행한다.
- 카메라 촬영 또는 갤러리에서 선택한 이미지를 입력으로 받아 분류 결과를 반환한다.
- 모델 사양에 맞게 이미지 크기 조정, 색상 채널 처리, 정규화 등의 전처리를 구현한다.
- 모델 출력값을 해석하여 클래스명과 신뢰도 등의 결과를 제공한다.
- 모델 로딩과 추론 코드를 분리하여 양자화 등 모델 최적화에 대응할 수 있도록 한다.
- 모델 파일은 앱 자산으로 관리하거나 별도의 초기화 절차를 통해 제공한다.
- Flutter 호환 패키지를 우선 검토하고, 필요한 경우 Android 및 iOS 네이티브 연동을 구현한다.

## 4. 텍스트 인식(OCR)

### 기술 스택
- **OCR Technology:** Google ML Kit Text Recognition
- **OCR Model:** ML Kit 내장 OCR 모델
- **Execution Environment:** On-device Inference

### 구현 지침
- ML Kit 기반 OCR을 사용하여 이미지에서 텍스트를 추출한다.
- Flutter 호환 플러그인을 우선 사용한다.
- 카메라 촬영 이미지와 갤러리 이미지를 OCR 입력으로 지원한다.
- 인식된 텍스트를 추출하고 필요한 경우 줄 또는 블록 단위로 정리한다.
- OCR 지원 목표는 한글과 영어이며, 혼합 문서도 검증한다. 현재 Latin 전용 구현은 후속 작업에서 교체한다.
- 인식 결과가 없거나 이미지 처리에 실패한 경우 예외 처리를 수행한다.
- 이미지 분류와 OCR을 독립적인 모듈로 구성하고 개별 테스트가 가능하도록 한다.
- 추가 OCR 모델을 도입할 경우 기존 ML Kit 구현과 분리하여 교체할 수 있도록 설계한다.

## 5. 전체 구현 원칙

### 5.1. Offline-first
- 핵심 기능과 분석 이력 관리는 로컬 환경에서 동작하도록 구현한다.
- 네트워크 연결이 끊겨도 기본적인 이미지 분석과 이력 관리가 가능해야 한다.
- Firebase는 로컬 기능의 필수 의존성이 되지 않도록 한다.

### 5.2. Modular Architecture
- 이미지 분류, OCR, 로컬 저장소, Firebase 동기화 기능을 독립적인 모듈로 분리한다.
- 각 모듈의 책임을 명확히 하고 불필요한 의존성을 최소화한다.
- 데이터 접근 로직과 UI 로직을 분리한다.

### 5.3. Reusable UI
- 공통 위젯과 화면 구성 요소를 재사용한다.
- 일관된 UI 스타일과 사용자 경험을 유지한다.
- 중복되는 UI 및 비즈니스 로직을 최소화한다.

### 5.4. Error Handling
- 이미지 입력 실패, 모델 로딩 실패, OCR 오류, 저장 실패 및 네트워크 오류를 처리한다.
- 사용자에게 이해하기 쉬운 오류 메시지를 제공한다.
- 오류 발생 시 앱이 비정상 종료되지 않도록 예외 처리를 구현한다.

### 5.5. Maintainability
- 데이터 모델, 서비스, UI 계층의 책임을 명확히 분리한다.
- 변수명, 함수명 및 파일명에 일관된 네이밍 규칙을 적용한다.
- 불필요한 코드 중복과 과도한 추상화를 피한다.
- 기존 프로젝트의 코드 스타일과 아키텍처를 우선적으로 따른다.

### 5.6. Cross-platform Compatibility
- Android와 iOS에서 패키지 및 네이티브 기능의 호환성을 확인한다.
- 플랫폼별 권한 설정과 네이티브 구성이 필요한 경우 각각 적용한다.
- 특정 플랫폼에서만 지원되는 기능은 명확하게 구분하여 처리한다.

### 5.7. Testing
- 이미지 분류, OCR, 로컬 저장 및 데이터 조회 기능을 개별적으로 테스트한다.
- 주요 비즈니스 로직에 대한 단위 테스트를 작성한다.
- 실제 기기에서 이미지 처리, 로컬 저장 및 플랫폼별 동작을 검증한다.
- 변경 사항 적용 후 가능한 범위에서 테스트와 빌드를 수행한다.

## 6. 구현 시 주의사항

- 문서에 기술 스택이 명시되어 있다는 이유만으로 해당 기능이 이미 구현되었다고 가정하지 않는다.
- 작업을 시작하기 전에 프로젝트 디렉터리 구조, 의존성, 설정 파일 및 기존 구현 상태를 확인한다.
- 이미 구현된 기능은 불필요하게 재작성하지 않는다.
- 모델 파일과 패키지의 실제 호환성을 확인하고 검증되지 않은 API나 의존성을 임의로 사용하지 않는다.
- 패키지는 공식 문서와 현재 Flutter SDK 버전의 호환성을 확인한 후 추가한다.
- 구현 후 가능한 범위에서 빌드 및 테스트를 수행하고 오류를 해결한다.
- 모델 파일이 제공되지 않았다면 파일이 존재한다고 가정하지 말고 필요한 파일과 적용 절차를 명시한다.
- 별도의 요구사항이 없다면 핵심 분석 기능은 Firebase 연결 없이도 실행 가능해야 한다.
- 기존 아키텍처와 충돌하는 경우 기존 구조를 최대한 유지하면서 필요한 부분만 개선한다.

## 7. 구현 우선순위

### 1단계: 프로젝트 구조 및 개발 환경 확인
- Flutter 및 Dart 버전 확인
- FVM 설정 확인
- 의존성 및 기존 구현 상태 확인
- 기존 디렉터리 구조와 아키텍처 파악

### 2단계: 핵심 분석 기능 구현
- 카메라 및 갤러리 이미지 입력
- LiteRT 기반 이미지 분류
- ML Kit 기반 OCR
- 분석 결과 화면 구현

### 3단계: 로컬 데이터 관리 구현
- 분석 결과 저장
- 분석 이력 조회 및 삭제
- 앱 재실행 후 데이터 유지
- 로컬 데이터 오류 처리

### 4단계: UI 및 예외 처리 개선
- 로딩 및 오류 상태 처리
- 공통 위젯 구성
- 사용자 경험 개선
- 입력 및 처리 실패 상황 대응

### 5단계: Firebase 동기화 확장
- 필요한 경우 사용자 인증 구현
- Cloud Firestore 데이터 구조 설계
- 사용자별 접근 제어 설정
- 기기 간 분석 이력 동기화 구현

### 6단계: 검증 및 안정화
- 단위 테스트 및 통합 테스트
- Android 및 iOS 빌드 검증
- 실제 기기에서 주요 기능 테스트
- 발견된 오류 수정
