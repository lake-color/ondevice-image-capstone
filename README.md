# 온디바이스 사진 분석 앱

주제 #2107 사진 분석 앱의 소스 저장소입니다. 코드는 3단계(MP3) 제출물과 같습니다.
카메라 촬영과 갤러리 선택으로 사진을 가져와 표시하고, 권한 요청·거부와 선택 취소 같은 예외 흐름을 처리합니다.
고른 사진의 글자를 기기 안에서 인식하고, 결과와 처리 시간을 화면에 표시합니다.
분석 결과를 로컬 이력으로 저장하고 OS 공유 시트로 다른 앱에 전달합니다. 원본 사진은 저장하지 않습니다.
저장하는 것과 저장하지 않는 것은 [PRIVACY.md](docs/submission/MP3/PRIVACY.md)에 정리했습니다.

## 단계 구성

각 단계는 앞 단계의 앱에 기능을 더해 만듭니다. 앞 단계의 코드와 이 문서의 내용은 다음 단계에도 그대로 들어갑니다.

| 단계 | 더해지는 기능 |
|---|---|
| MP1 | 카메라·갤러리 입력, 권한 요청과 거부 안내, 예외 처리 |
| MP2 | 온디바이스 텍스트 인식(선택 기능)과 사물 분류, 처리 시간 측정, 인식 불가 안내 |
| MP3 | 로컬 분석 이력(저장·목록·삭제), OS 공유 시트, 원본 사진을 남기지 않는 프라이버시 설계 |

## 전체 기능 목록

### 사진 입력 (MP1)

- 카메라 촬영과 갤러리 선택으로 사진 가져오기, 미리보기와 파일 이름 표시
- 권한이 필요한 이유를 사진 가져오기 시트에서 먼저 설명
- 카메라 권한을 촬영을 고른 시점에 요청
- 권한 거부 시 안내 카드 표시, **설정에서 권한 열기**로 앱 설정 화면 이동
- 선택 취소, 입력 오류 시 크래시 없이 안내

### 온디바이스 분석 (MP2)

- 텍스트 분석: 사진 속 한글·영어·숫자 인식 (선택 기능)
- 사물 분석: ImageNet 클래스 이름과 신뢰도 표시. 구현은 끝났으나 모델 정확도 때문에 수정이 필요합니다.
- 처리 시간 측정과 표시
- 인식할 수 없는 사진을 오류가 아닌 안내로 처리
- 분석 취소
- 네트워크 없이 동작(비행기 모드에서 검증)

### 이력과 공유 (MP3)

- 분석이 끝나면 결과를 자동으로 로컬 이력에 저장
- 이력 목록: 최신순으로 분석 방식, 결과 첫 줄, 신뢰도, 처리 시간, 분석 시각 표시
- 이력 개별 삭제: 삭제 전 확인, 삭제 후 복구 불가
- 앱을 다시 실행해도 이력 유지
- 결과 화면과 이력 화면의 **결과 공유하기**로 OS 공유 시트를 열어 결과 텍스트 전달
- 이력이 없을 때 빈 상태 안내, 저장 실패 시 분석 결과를 유지한 채 저장만 다시 시도
- 이력 파일을 읽지 못하면 기존 파일을 덮어쓰지 않고 다시 시도 안내

### 프라이버시 설계 (MP3)

- 이력에는 결과 텍스트만 저장하고 사진 파일과 경로는 저장하지 않음
- 사진 선택기가 만든 임시 사본은 사진을 바꾸거나 화면을 나갈 때 삭제
- 공유할 때 사진은 포함하지 않음
- 서버 전송 없음, Android 클라우드 백업 제외

## 화면 흐름

1. 시작 화면에서 **시작하기**를 누르면 사진 선택 화면으로 이동합니다.
2. **사진 가져오기**를 누르면 하단 시트에서 **카메라로 촬영** 또는 **갤러리에서 선택**을 고릅니다.
3. 가져온 사진이 화면 중앙에 표시되고, 아래에 파일 이름이 나타납니다.
4. **다른 사진 선택**으로 사진을 바꿀 수 있습니다.
5. **텍스트 분석** 또는 **사물 분석**을 누르면 분석 중 화면을 거쳐 결과 화면으로 이동합니다. 사진을 고르기 전에는 두 버튼이 비활성 상태입니다.
6. 결과 화면에 원본 사진, 결과, 처리 시간을 표시합니다. 분석 중 화면의 **분석 취소**를 누르면 돌아가고, 늦게 도착한 결과는 버립니다.
7. 결과 화면의 **다른 사진 분석**을 누르면 사진 선택 화면으로 돌아갑니다.
8. 결과는 이력에 저장되며, 결과 화면의 **결과 공유하기**로 OS 공유 시트를 엽니다.
9. 사진 선택 화면의 **분석 이력 보기**에서 이력을 보고, 항목을 삭제하거나 가장 최근 결과를 공유합니다.

## 권한 처리 흐름

### 필요한 권한과 요청 시점

| 경로 | Android | iOS |
|---|---|---|
| 카메라 촬영 | `CAMERA` 권한을 촬영 시점에 요청 | `NSCameraUsageDescription` 문구와 함께 요청 |
| 갤러리 선택 | 시스템 사진 선택기를 사용해 권한이 필요 없음 | `NSPhotoLibraryUsageDescription` 문구와 함께 요청 |

- 권한은 앱을 켤 때가 아니라 사용자가 해당 경로를 고른 시점에 요청합니다.
- Android 갤러리는 사용자가 고른 사진 한 장만 앱에 전달되므로 저장소 권한을 선언하지 않았습니다.
- `AndroidManifest.xml`에는 `CAMERA` 권한과, 카메라가 없는 기기에서도 설치되도록 `android.hardware.camera`를 `required="false"`로 선언했습니다.

### 권한 설명 문구

권한을 요청하기 전에 왜 필요한지 먼저 알립니다.

| 위치 | 문구 |
|---|---|
| 사진 가져오기 시트 · 카메라 | 촬영을 위해 카메라 권한을 요청해요. 사진은 기기 안에서만 사용합니다. |
| 사진 가져오기 시트 · 갤러리 | 직접 고른 사진 한 장만 앱에 전달됩니다. |
| iOS 카메라 권한 대화상자 | 사진을 촬영하여 기기에서 분석하기 위해 카메라 접근이 필요합니다. |
| iOS 사진 권한 대화상자 | 선택한 사진을 기기에서 분석하기 위해 사진 보관함 접근이 필요합니다. |

### 거부했을 때

1. `image_picker`가 권한 거부 오류(`camera_access_denied`, `camera_access_restricted`, `photo_access_denied`, `photo_access_restricted`)를 돌려줍니다.
2. `ImageInputService`가 이를 `ImagePermissionDeniedException`으로 바꿉니다.
3. 사진 선택 화면이 **권한 거부** 안내 카드를 띄웁니다. 거부된 경로에 따라 문구가 달라집니다.
   - 카메라: "카메라 권한이 필요해요 — 설정 > 권한 > 카메라에서 허용할 수 있어요. 허용하지 않아도 갤러리 선택은 계속 사용할 수 있습니다."
   - 갤러리: "사진 접근 권한이 필요해요 — 설정 > 권한 > 사진에서 허용할 수 있어요. 허용하지 않아도 카메라 촬영은 계속 사용할 수 있습니다."
4. **설정에서 권한 열기**를 누르면 이 앱의 OS 설정 화면이 열립니다. 한 번 거부하면 OS가 다시 묻지 않을 수 있어 설정 이동이 유일한 복구 경로입니다.
5. 닫기(X)를 누르면 안내만 닫히고, 다른 경로로 사진을 계속 가져올 수 있습니다.

## 예외 처리

| 상황 | 동작 |
|---|---|
| 사진 가져오기 시트를 선택 없이 닫음 | 아무 일도 일어나지 않고 화면이 그대로 유지됩니다. |
| 카메라·갤러리에서 선택을 취소함 | `image_picker`가 `null`을 돌려주며, 기존 화면(빈 상태 또는 이전 사진)을 유지합니다. |
| 권한 거부 | 크래시 없이 권한 거부 안내 카드를 표시합니다. |
| 권한 외의 입력 오류 | 플랫폼 원문 대신 "사진을 불러오지 못했습니다. 다시 시도해 주세요."를 스낵바로 표시합니다. |
| 설정 화면을 열지 못함 | "설정을 열지 못했습니다. 기기 설정에서 앱 권한을 직접 변경해 주세요."를 표시합니다. |
| 사진 파일을 표시할 수 없음 | 미리보기 자리에 "사진을 불러올 수 없습니다. 다시 선택해 주세요."를 표시합니다. |
| 가져오는 도중 버튼을 다시 누름 | 진행 중에는 버튼과 미리보기 영역을 비활성화해 중복 실행을 막습니다. |

로딩 표시는 사진 가져오기가 끝난 뒤에 내리고, 그다음에 권한 안내를 띄웁니다. 안내 뒤에서 로딩이 계속 도는 일이 없습니다.

## 선택한 분석 기능과 라이브러리

**선택한 분석 기능은 텍스트 인식(OCR)입니다.**

| 항목 | 내용 |
|---|---|
| 분석 기능 | 텍스트 인식 — 사진 속 한글·영어·숫자 |
| 라이브러리 | Google ML Kit Text Recognition v2 (`google_mlkit_text_recognition` 0.17.1), 한국어 스크립트 모델 |
| 실행 위치 | 기기 내부. 한국어 모델은 앱에 번들로 포함되어 다운로드 없이 동작합니다. |
| 호출 경로 | `AnalysisService.analyze` → `MlKitOcrAnalyzer.recognize` |

### 사물 분류에 대하여

사물 분류(**사물 분석** 버튼)도 구현은 끝나 있고 소스에 그대로 들어 있습니다.
TensorFlow Lite로 앱에 내장한 MobileNetV3 Small 모델을 실행해 ImageNet 클래스 이름과 신뢰도를 표시합니다.

다만 모델 정확도 때문에 수정이 필요해 선택 기능으로 내세우지 않았습니다.

- 이전 검증에서 빨간 사과 사진을 `pomegranate`(석류, 신뢰도 78.9%)로 분류했습니다.
- ImageNet 1,000개 클래스만 구분하므로 클래스에 없는 사물은 엉뚱한 이름이 나옵니다.
- 신뢰도 50% 미만 결과에는 "신뢰도가 낮은 추정 결과입니다" 안내를 붙이지만, 위 사례처럼 높은 신뢰도로 틀리는 경우는 걸러내지 못합니다.

대표 사진으로 정확도를 평가한 뒤 모델 교체나 재학습 여부를 정할 계획입니다.

## 처리 시간 측정값

### 측정 방법

- 측정 구간은 `AnalysisService.analyze` 내부의 `Stopwatch`입니다. 분석기 호출 직전부터 결과를 받을 때까지이며, 결과 화면의 "처리 시간"과 같은 값입니다.
- 텍스트 인식에는 인식기 생성, 이미지 파일 읽기, 추론, 인식기 해제가 포함됩니다.
- 측정 환경: Pixel 9 Pro 에뮬레이터(Android 16, x86_64), 프로파일 빌드.
- 반복 측정은 `test/integration/processing_time_device.dart`로 수행했습니다. 기기에서 직접 그린 1200×800 PNG(한글·영어·숫자 4줄)를 10회 연속 분석합니다.

### 텍스트 인식 (선택 기능)

| 조건 | 첫 실행 | 2~10회 평균 | 최소 | 최대 | 10회 평균 |
|---|---|---|---|---|---|
| 네트워크 연결 | 479 ms | 222.8 ms | 212 ms | 479 ms | 248.4 ms |
| 비행기 모드 | 484 ms | 230.6 ms | 210 ms | 484 ms | 255.9 ms |

- 10회 측정값(네트워크 연결): 479, 235, 215, 239, 212, 214, 215, 228, 216, 231 ms
- 10회 측정값(비행기 모드): 484, 244, 219, 239, 219, 251, 227, 224, 242, 210 ms
- 첫 실행은 모델을 메모리에 올리는 시간이 더해져 약 0.48초이고, 이후에는 약 0.21~0.25초입니다.
- 비행기 모드와 네트워크 연결 상태의 차이는 측정 오차 범위 안입니다. 분석이 네트워크에 의존하지 않는다는 뜻입니다.

앱 화면에서 직접 잰 값(갤러리에서 고른 1200×900 PNG, MP2 스크린샷):

| 조건 | 화면 표시값 |
|---|---|
| 네트워크 연결, 앱 실행 후 첫 분석 | 0.61초 |
| 비행기 모드, 두 번째 분석 | 0.44초 |

### 참고: 인식 불가 이미지와 사물 분류

| 대상 | 측정값 |
|---|---|
| 글자가 없는 이미지의 텍스트 인식(안내로 끝나는 경우) | 53~78 ms (3회) |
| 사물 분류, 네트워크 연결 | 평균 297.5 ms (291~315 ms, 10회) |
| 사물 분류, 비행기 모드 | 평균 309.2 ms (297~323 ms, 10회) |

사물 분류 시간에는 이미지 디코딩, 전처리, 모델 로드, 추론이 모두 포함됩니다.
에뮬레이터는 PC의 CPU로 동작하므로 실제 휴대폰의 속도와 다르며, 실기기에서는 측정하지 않았습니다.

## 인식 불가 처리 방식

글자를 찾지 못한 사진은 오류가 아니라 정상적인 결과 중 하나로 보고 안내로 처리합니다.

1. ML Kit가 빈 문자열을 돌려주면 `MlKitOcrAnalyzer`가 사용자용 문구를 담은 `AnalysisException`을 던집니다.
2. 분석 중 화면이 이를 받아 **인식 불가** 안내 카드를 표시합니다.
   - 제목: 분석할 정보를 찾지 못했어요
   - 본문: 사진에서 인식할 텍스트를 찾지 못했습니다. 글자가 또렷하게 보이는 사진으로 다시 시도해 주세요.
   - 버튼: **다른 사진 분석** — 사진 선택 화면으로 돌아갑니다.
3. 앱은 종료되지 않고, 기술적인 오류 원문도 화면에 노출하지 않습니다.

| 그 밖의 상황 | 동작 |
|---|---|
| ML Kit 내부 오류(손상된 파일 등) | "텍스트를 인식하지 못했습니다. 다른 사진으로 다시 시도해 주세요." 안내 |
| 예상하지 못한 오류 | **분석 실패** 배지와 "다른 사진을 선택하거나 분석 방식을 바꿔보세요." 안내. 오류 원문은 숨깁니다. |
| 사물 분류에서 이미지를 읽지 못함 | `AnalysisException` 문구를 같은 안내 카드로 표시 |
| 사물 분류 신뢰도 50% 미만 | 결과는 보여주되 "신뢰도가 낮은 추정 결과입니다" 문구를 함께 표시 |

## 온디바이스 실행 검증 (비행기 모드)

1. 에뮬레이터에서 비행기 모드를 켜고, `ping 8.8.8.8`이 "Network is unreachable"로 실패하는 것을 확인했습니다.
2. 그 상태에서 갤러리로 사진을 고르고 텍스트 분석을 실행해 결과를 얻었습니다(상태 표시줄에 비행기 아이콘).
3. 같은 상태에서 처리 시간 테스트를 실행해 텍스트 인식 10회와 사물 분류 10회가 모두 통과했습니다.
4. 글자가 없는 이미지의 인식 불가 안내도 비행기 모드에서 확인했습니다.

코드에도 분석을 위한 네트워크 호출이 없습니다. 사진은 기기 안의 파일 경로로만 분석기에 전달됩니다.

## 이력 데이터 구조

### 파일

- 위치: 앱 지원 디렉터리의 `analysis_history.json` (Android `files/`, iOS Application Support)
- 형식: UTF-8 JSON 문서 하나. 변경할 때마다 전체를 다시 씁니다.
- 쓰기 방식: 임시 파일(`analysis_history.json.tmp`)에 먼저 쓰고 flush한 뒤 이름을 바꿔 교체합니다. 쓰는 도중 앱이 종료되어도 기존 파일이 깨지지 않습니다.

### 구조

```json
{
  "version": 1,
  "entries": [
    {
      "id": "1794733980786556",
      "result": {
        "method": "ocr",
        "sourceName": "scaled_49.png",
        "title": "인식된 텍스트",
        "content": "온디바이스 사진 분석\n회의록 2026년 11월 15일\nOn-device OCR Test 123\n사진은 서버로 보내지 않습니다.",
        "durationMicroseconds": 579308,
        "createdAt": "2026-11-15T09:13:00.786556",
        "confidence": null
      }
    }
  ]
}
```

위 내용은 에뮬레이터에서 실제로 저장된 파일입니다.

| 필드 | 타입 | 설명 |
|---|---|---|
| `version` | 정수 | 파일 형식 버전. 현재 `1`. 다른 값이면 읽지 않고 파일을 보존합니다. |
| `entries` | 배열 | 이력 항목. 최신 항목이 앞에 옵니다. |
| `entries[].id` | 문자열 | 항목 ID. 분석 시각의 마이크로초 값이며, 겹치면 `-1`, `-2`를 붙입니다. |
| `result.method` | 문자열 | `ocr` 또는 `imageClassification` |
| `result.sourceName` | 문자열 | 사진 선택기가 임시 사본에 붙인 파일 이름. 경로는 없습니다. |
| `result.title` | 문자열 | `인식된 텍스트` 또는 `분류 결과` |
| `result.content` | 문자열 | 인식한 텍스트 또는 분류 라벨 |
| `result.durationMicroseconds` | 정수 | 처리 시간(마이크로초) |
| `result.createdAt` | 문자열 | 분석 시각(ISO 8601, 기기 현지 시각) |
| `result.confidence` | 실수 또는 `null` | 사물 분류 신뢰도(0~1). 텍스트 인식은 `null` |

원본 사진, 사진 경로, 썸네일에 해당하는 필드는 없습니다. 메모리의 `AnalysisResult.imagePath`는 결과 화면 미리보기에만 쓰이고 `toJson`에서 제외됩니다.

### 코드 구성

| 파일 | 역할 |
|---|---|
| `lib/domain/analysis_result.dart` | 결과 모델과 JSON 변환, 공유 문구 생성 |
| `lib/domain/analysis_history.dart` | ID와 결과를 묶은 이력 항목 |
| `lib/data/history_storage.dart` | 파일 읽기와 안전한 쓰기 |
| `lib/data/analysis_history_store.dart` | 불러오기·추가·삭제, 작업 순서 보장, 화면 갱신 알림 |
| `lib/page/history_page.dart` | 이력 목록, 삭제 확인, 공유 |
| `lib/service/share_service.dart` | OS 공유 시트 호출 |

- 추가와 삭제는 순서대로 실행해, 느린 쓰기가 나중 변경을 덮어쓰지 않습니다.
- 파일 쓰기가 성공한 뒤에만 화면의 목록을 바꿉니다.
- 전체 삭제와 이력 수정 기능은 없습니다.

## 프라이버시

- 이력에는 결과 텍스트만 저장합니다. 사진 파일, 사진 경로, 썸네일은 저장하지 않습니다.
- 사진 선택기가 앱 캐시에 만든 임시 사본은 사진을 바꾸거나 사진 선택 화면을 나갈 때 삭제합니다.
- 공유할 때는 결과 텍스트만 전달하고, Android 클라우드 백업에서 이력 파일을 제외했습니다.

항목별 이유와 확인하지 못한 부분은 [PRIVACY.md](docs/submission/MP3/PRIVACY.md)에 정리했습니다.

## 실행 절차

FVM과 Android 또는 iOS 개발 도구를 설치하고 기기나 에뮬레이터를 연결합니다. iOS 빌드에는 macOS와 Xcode가 필요합니다.
PATH의 `flutter`가 다른 버전이면 `pub get`이 실패하므로 `fvm flutter`를 사용합니다.

```sh
fvm flutter pub get
fvm flutter run
```

검증 명령:

```sh
fvm flutter analyze
fvm flutter test
fvm flutter build apk --debug
```

권한 거부를 다시 재현하려면 권한을 초기화합니다.

```sh
adb shell pm revoke com.example.ondevice_image_capstone android.permission.CAMERA
adb shell pm clear-permission-flags com.example.ondevice_image_capstone android.permission.CAMERA user-set user-fixed
```

처리 시간 측정(기기 또는 에뮬레이터 필요). 출력의 `TIMING ocr`, `TIMING ocr-no-text`, `TIMING classification` 줄이 측정값입니다.

```sh
fvm flutter drive --profile --driver=test/integration/driver.dart --target=test/integration/processing_time_device.dart -d <device-id>
```

비행기 모드 전환:

```sh
adb shell cmd connectivity airplane-mode enable
adb shell cmd connectivity airplane-mode disable
```

저장된 이력 파일과 캐시를 직접 확인하는 방법(디버그 빌드):

```sh
adb shell run-as com.example.ondevice_image_capstone cat files/analysis_history.json
adb shell run-as com.example.ondevice_image_capstone ls -R cache
```

재시작 후 유지 확인:

```sh
adb shell am force-stop com.example.ondevice_image_capstone
```

기기 통합 테스트 전체 목록은 `test/README.md`를 참고하세요.

## 민감정보

- 테스트에는 인물 사진을 쓰지 않았습니다. 갤러리 이미지는 직접 그린 글자·도형 이미지이고, 카메라 이미지는 에뮬레이터의 가상 장면입니다.
- 원본 사진 파일은 제출물에 없습니다. 스크린샷에는 테스트 이미지가 화면에 표시된 모습만 담겨 있습니다.
- 앱에는 사진을 서버로 보내는 코드가 없습니다. 기본 매니페스트는 네트워크 권한을 선언하지 않으며, 디버그·프로파일 매니페스트의 `INTERNET`은 Flutter 개발 도구용입니다.
- API 키, 계정 정보, 서명 키는 소스에 없습니다.
- 빌드 산출물과 로컬 경로가 담기는 생성 파일(`build/`, `.dart_tool/`, `android/local.properties` 등)은 제출물에서 제외했습니다.
