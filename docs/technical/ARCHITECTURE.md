# 기술 구성

현재 코드 기준입니다. 검증 결과와 남은 작업은 [진행 현황](../STATUS.md)을 참고하세요.

## 기술 스택

| 영역 | 현재 구성 |
|---|---|
| 앱 | Flutter 3.47.5, Dart 3.13.4, FVM |
| 플랫폼 | Android API 26 이상, iOS Podfile 기준 15.5 이상 |
| 사진 입력 | `image_picker` — 카메라·갤러리 |
| 사물 분류 | MobileNetV3 Small, `tflite_flutter`, `image` |
| OCR | `google_mlkit_text_recognition`, 한국어 ML Kit 모델 |
| 저장 | `path_provider`, 앱 지원 디렉터리의 JSON 파일 |
| 상태·화면 이동 | `setState`, `ChangeNotifier`, `Navigator` |
| 결과 복사 | Flutter `Clipboard` |

패키지 제약은 [pubspec.yaml](../../pubspec.yaml), 설치 버전은
[pubspec.lock](../../pubspec.lock)에서 관리합니다. Firebase는 설치·연결되지 않았으며,
인증·Firestore·보안 규칙을 포함한 기기 간 동기화는 선택적 후속 기능입니다.

## 구조와 처리 흐름

- `lib/app/`: 서비스 생성과 주입, 라우팅, 테마
- `lib/page/`: 시작·사진 선택·로딩·결과·이력 화면
- `lib/service/`: 입력, 분석 분기, OCR, 분류, 클립보드 복사
- `lib/domain/`: 분석 방식과 결과·이력 모델
- `lib/data/`: 이력 상태 관리와 파일 입출력

`main.dart` → `App`에서 실제 서비스를 연결합니다. 사진 선택 후
`AnalysisService`가 OCR 또는 분류를 실행하고, `LoadingPage`가 이력을 저장한 뒤
결과 화면으로 이동합니다. 저장 실패 시 분석 결과를 유지하여 저장만 재시도합니다.

분류는 이미지 전처리와 추론을 별도 isolate에서 수행합니다. 모델 바이트·라벨은
캐시하고 interpreter는 요청별로 생성·해제합니다. 상세 사양은
[이미지 분류](IMAGE_CLASSIFICATION.md)에 정리했습니다.
OCR은 한국어 인식기로 한글·영어를 처리하며, 빈 결과와 처리 실패를 안내하고
사용 후 인식기를 닫습니다.

## 로컬 이력과 데이터 범위

- 저장 파일: 앱 지원 디렉터리의 `analysis_history.json`
- 형식: `version: 1`, 최신순 `entries` 목록, 항목별 고유 ID와 분석 결과
- 결과 필드: 분석 방식, 원본 파일명, 제목, 결과 텍스트, 처리 시간, 생성 시각, 신뢰도
- 원본 사진 바이트와 사진 경로는 직렬화하지 않습니다. 현재 결과 미리보기에만 경로를 사용합니다.
- 읽기 실패·손상 데이터·지원하지 않는 버전은 기존 파일을 보존하고 재시도를 안내합니다.
- 변경 작업은 순서대로 실행하며, 임시 파일 기록·flush·교체가 성공한 뒤 메모리 상태를 갱신합니다.
- 같은 시각의 결과도 ID 접미사로 구분합니다. 저장소는 추가·개별 삭제·전체 삭제를 지원하며,
  현재 화면은 개별 삭제를 제공합니다. 이력 수정 기능은 없습니다.
- 앱 삭제·데이터 초기화 후 복구와 기기 간 동기화는 지원하지 않습니다.

사진·분석 결과를 서버로 전송하는 앱 기능은 없습니다. 결과 공유 버튼은 클립보드
복사이며 OS 공유창은 연결하지 않았습니다. 사진 선택 플러그인의 임시 파일과
OS 백업 정책은 이력 저장 정책과 별개이며, 제출용 개인정보 문서 작성 시 확인해야 합니다.

## 유지할 설계 원칙

핵심 기능은 오프라인에서 동작하고, 원본 사진은 이력에 넣지 않습니다.
UI·분석·저장 책임을 분리하되 과도한 계층을 추가하지 않습니다.
서비스 인터페이스로 실제 구현과 테스트 대역을 교체하며, 가짜 분석 결과를 실제 결과로 표시하지 않습니다.
모델 변경 시 텐서 형태뿐 아니라 정규화·출력 의미·라벨 순서도 확인합니다.
플랫폼별 검증 결과는 구분하여 기록합니다.
